# ブートローダー設計メモ

## 二段ブート構成

| ステージ | ロード先 | サイズ | 役割 |
| --- | --- | --- | --- |
| Stage1 | `0x0000:0x7C00` | 512 バイト固定 | BIOS が読み込む。Stage2 を読んでジャンプするだけ |
| Stage2 | `0x0000:0x7E00` | 最大 17 セクタ (8704 バイト) | 本体 |

BIOS がやってくれるのは「ブートセクタ 1 個 (512 バイト) を 0x7C00 に読んで
そこへジャンプする」ことだけなので、512 バイトに収まらない処理は
Stage2 に追い出す必要がある。これが二段構成の理由。

## disk.img のレイアウト (1.44MB フロッピー)

```
オフセット           内容
0x000000 - 0x0001FF  Stage1 (512 バイト、末尾 0x1FE-0x1FF が 55 AA)
0x000200 - ...       Stage2 (Stage1 が 17 セクタ分まとめて読み込む)
...      - 0x167FFF  0 埋め
合計 1,474,560 バイト
```

## 実行時のメモリマップ (リアルモード中)

```
0x00000 - 0x003FF   割り込みベクタテーブル (触ってはいけない)
0x00400 - 0x004FF   BIOS データエリア      (触ってはいけない)
0x00500 - 0x07BFF   空き。E820 のメモリマップ格納に使用 (E820_BUF)
        - 0x07C00   スタック (0x7C00 から下方向へ伸びる)
0x07C00 - 0x07DFF   Stage1
0x07E00 - 0x09FFF   Stage2 (17 セクタ分の領域)
0x0A0000 -          VGA / BIOS 領域
0x0B8000 -          テキストモード VRAM (1文字 = 文字コード1バイト + 属性1バイト)
```

プロテクトモード移行後は `esp = 0x00090000` を 32bit 用スタックに使っている。

## 互換性のための設計判断

### ブートドライブ番号を決め打ちしない

引き継ぎ資料 5章(2) にある通り、`MOV DL, 80h` を決め打ちしていたために
フロッピーブートで `INT 13h` が失敗し、ダブルフォルト (TRAP/08) 連発の
無限リブートループに陥った経緯がある。

対策として `MOV DL, 00h` にすれば VirtualBox のフロッピーブートでは動くが、
これも決め打ちであることに変わりはない。USB-FDD エミュレーションなどでは
BIOS が `0x00` 以外の番号を割り当てることがある。

**BIOS はブート時に `DL` にブートドライブ番号を入れて渡してくれる**ので、
Stage1 は最初にこれを保存し、以後ずっとその値を使う。
Stage2 にも `DL` 経由で中継している。

### 読み込みは CHS (INT 13h AH=02h) のみ

LBA 拡張読み込み (`AH=42h`) はフロッピーの BIOS では未対応のことが多いので
Stage1 では使わない。Stage2 が読むのはシリンダ0 / ヘッド0 の
セクタ 2〜18 (1 トラック 18 セクタのうち Stage1 を除いた 17 個) なので、
トラックをまたがず 1 回の `INT 13h` で完結する。

1MB 超へカーネルを読み込むフェーズ2-B では拡張読み込みが必要になるので、
そこで「`AH=41h` で対応チェック → 非対応なら CHS + ビッグリアルモード」
というフォールバックを入れる。

### 読み込みリトライ

実機のフロッピードライブはモータの回転待ちで初回の読み込みが失敗することがある。
`INT 13h AH=00h` (ディスクリセット) を挟んで 5 回までリトライする。

### A20 ゲートは 3 方式フォールバック

`enable_a20` は次の順に試し、そのつど**実際にラップアラウンドするか検証**する
(`check_a20`)。BIOS の戻り値を信用せず、`0000:0500` と `FFFF:0510` が
同じ物理アドレスを指すかどうかを書き込んで確かめる。

1. 既に有効か確認（最近のマシンは BIOS が有効にしている）
2. `INT 15h AX=2401h` — 最も安全。対応していればこれで済む
3. キーボードコントローラ (8042) の出力ポート bit1 — 枯れているがタイミング依存
4. 高速 A20（ポート `0x92`）の bit1 — 一部機種でリセットが掛かるので最後

ポート `0x92` の **bit0 は Fast Reset** なので、絶対に立てないよう
`and al, 0xFE` で必ず落としている。

### メモリマップ取得も 3 方式フォールバック

1. `INT 15h EAX=E820h` — 詳細なメモリマップが取れる。Linux Boot Protocol でも必須
2. `INT 15h AX=E801h` — E820 非対応の古い BIOS 向け
3. `INT 15h AH=88h` — 最も枯れている。64MB で頭打ちになる

E820 では ACPI 3.0 の拡張属性 (エントリ 20 バイト目の bit0) もチェックし、
0 のエントリは無視している。

## GDT

フラットモデル（コード・データとも base=0, limit=4GB）。

| セレクタ | 内容 | ディスクリプタ |
| --- | --- | --- |
| `0x00` | ヌルディスクリプタ（必須） | `0000000000000000` |
| `0x08` | 32bit コードセグメント | limit=`0xFFFFF`, base=0, access=`0x9A`, flags=`0xCF` |
| `0x10` | 32bit データセグメント | limit=`0xFFFFF`, base=0, access=`0x92`, flags=`0xCF` |

- access `0x9A` = P=1 / DPL=0 / S=1 / type=1010（実行可・読み取り可）
- access `0x92` = P=1 / DPL=0 / S=1 / type=0010（データ・書き込み可）
- flags `0xCF` = G=1（4KB 粒度）/ D=1（32bit）/ limit の上位 4bit = `F`

`lgdt` に渡すのはリミット (サイズ-1) 2 バイト + 線形アドレス 4 バイトの
6 バイト構造体。セグメント 0 で動いているのでラベルのオフセットが
そのまま線形アドレスになる。

## リアルモード → プロテクトモードの手順

1. `cli`（割り込み禁止）
2. NMI も止める（CMOS インデックスレジスタ `0x70` の bit7 を立てる）
3. A20 を有効化して検証
4. `lgdt [gdt_desc]`
5. `mov eax, cr0` / `or eax, 1` / `mov cr0, eax`（PE ビットを立てる）
6. `jmp GDT_CODE32:pm_entry` でパイプラインをフラッシュしつつ CS を載せ替える
7. 32bit 側で `ds/es/fs/gs/ss` をデータセレクタに、`esp` を設定

移行後は BIOS 呼び出し (`INT 10h` など) が使えなくなるので、
画面出力は VRAM `0xB8000` への直接書き込みで行う。
