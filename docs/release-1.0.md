# myOS 1.0

Windows 98 の見た目と操作感を目指した自作 OS の、最初の公開版。

ブートローダーは自作、カーネルは Linux（`.ko` を全て `=y` にした
モノリシック構成）、GUI 層は Xlib で自作。

## 版の付け方

| 系列 | 位置づけ |
| --- | --- |
| **1.x** | 開発版。動くものから順に出していく。実機で踏んだものを次の版で直す |
| **2.x** | 配布版。1.x でやることを全部終え、安定を確かめ、セキュリティを固めてから出す |

2.0 を出すまでは「試すなら自己責任で」の段階だと思ってほしい。

使った時点で、これに同意したものとする。**

消えて困るものは、始める前に別の場所へ写しておくこと。

Microsoft の著作物は一切含んでいない。

`x.y.z` の `y` と `z` は、カーネルを作り直したかどうかで決める。

| 桁 | 上げるとき |
| --- | --- |
| **y** | カーネルを作り直した (版を上げた / 設定を変えた)。`z` は 0 に戻す |
| **z** | カーネルはそのままで、それ以外だけ変えた |

`tools/build_kernel.sh` の中身で鍵を作っているので、**キャッシュが外れた =
カーネルが変わった**。ビルドの最後にどちらだったかを出すようにしてある。

(この決めは 1.5 のあとから適用する。1.4 と 1.5 はカーネルが同じなので、
 遡って当てはめると 1.4.1 になるが、出したタグを振り直すほうが害が大きい)

## 1.5.18 で直したもの

### OpenGL Test が歯車を回すだけだった

```
OpenGL Test|app|/usr/bin/glxgears
```

`glxgears` は fps を**標準出力に書く**。デスクトップのアイコンから
起動すると受け取る者が居ないので、数字はどこにも出ない。歯車が回って
終わり。「動いた」以上のことが何も分からなかった。

しかも本当に知りたいのは fps ではなく、**何が描いているか**のほう。

| 出るもの | 意味 |
| --- | --- |
| `Accelerated: no` / `llvmpipe` | **CPU が描いている。**3D は実用速度にならない |
| `Accelerated: yes` / それ以外 | GPU が描いている |

myOS はドライバを決め打ちせず X に選ばせているので、**GPU で描けて
いるかどうかは実際に見ないと分からない**。その唯一の窓口がこれなのに、
肝心のことを何も出していなかった。

`myos-gltest` を挟んで、端末に素性と fps の両方を流すようにした。

```
--- 何が描いているか ---
direct rendering: Yes
Device: llvmpipe (LLVM 20.1.2, 256 bits)
Accelerated: no
OpenGL renderer string: llvmpipe (...)

--- 5 秒ごとに fps。窓を閉じると止まる ---
6728 frames in 5.0 seconds = 1345.527 FPS
```

GPU を差し替えたときに、どちらが速いかを数字で決められる。

## 1.5.17 で直したもの

### HDMI を挿しても音の出口に出てこなかった

`pactl` の出力の読み方を間違えていた。ポートの行から
「挿さっているか」を `available:` という文字で探していたが、
**PulseAudio 16 (Debian 12) はそう書かない**。

```
hdmi-output-0: HDMI / DisplayPort (type: HDMI, priority: 5900,
    latency offset: 0 usec, availability group: Legacy 3, not available)
```

括弧の**最後の項目**がそれで、`available` / `not available` /
`availability unknown` の 3 通り。`available:` は無い。
古い pactl は `available: no` と書くので、そちらの記憶で書いていた。

しかも `availability group:` が紛らわしい。あれはポートの識別子で、
挿さっているかとは関係が無い。

結果、**ポートが 1 つも取れていなかった。** HDMI どころか何も出ない。

pactl の実物 (16.1) を落として、中に埋まっている書式文字列を読んで
確かめた。推測でなく、実際に使われている書式はこれ:

```
%s: %s (type: %s, priority: %u%s%s, %s)
```

新旧どちらの書き方も読めるようにした。行を拾う目印は `priority:` に
変えてある。ポートの行には必ずあり、書き方が版で変わらない。

### 動いている出口が「使われていない」扱いになっていた

同じところでもう 1 つ。動いているプロファイルは足し算で書かれる。

```
Active Profile: output:analog-stereo+input:analog-stereo
Part of profile(s): output:analog-stereo
```

丸ごと比べていたので一致せず、いま音が出ている出口にも印が付かな
かった。`+` で分解して、どれか 1 つでも一致すればよいことにした。

### 「全部出す」を付けた

繋がっていないものを隠す作りにした以上、**判定が外れたときに詰む**。
ジャック検出を持たないコーデック、ELD が来ていない HDMI、そして
今回のようなこちらの読み違い。

Sound タブに **Show all outputs** のチェックを足した。押せば
挿さっていないものも並ぶ (`(not detected)` と添える)。
1 つも出なかったときの文言も「Show all outputs を試して」に変えた。

**隠す機能には、必ず全部出す道を付けておく。**

## 1.5.16 で直したもの

### 正しいパスワードを入れても「管理者権限が要る」で転んでいた

実機で解像度を変えようとすると、こう出て止まった。

```
The command could not run:
sudo: パスワードが必要です
```

1.5.11 で myos-runas を 2 段に分けたときに作り込んだ回帰。

| | やっていたこと | 結果 |
| --- | --- | --- |
| 1 段目 | `sudo -S -k -v` | 認証は通る (終了状態 0) |
| 2 段目 | `sudo -n <cmd>` | **必ず**「パスワードが必要です」 |

原因は `-k` の意味を取り違えたこと。`man sudo` にこう書いてある。

> `-k` … in conjunction with … the `-v` option … **will not update the
> user's cached credentials**

つまり 1 段目は**認証を通すが、時刻印を残さない**。2 段目の `-n` は
残っていない時刻印を探しに行くので、100% 転ぶ。パスワードが正しいか
どうかとは無関係に転ぶ。

**2 段目にもパスワードを渡すようにした。** 時刻印には頼らない。

`-k` を外せば時刻印は残るが、そうすると「前に認証してから 15 分以内」の
間は**何を打っても素通り**する。パスワードを聞く画面が何も守らなく
なるので、そちらは採らない。渡す手間のほうを取る。

なお、この画面が出ていたこと自体は正常だった。ユーザーはちゃんと
`sudo` グループに入っている。sudoers に載っていなければ
`user is not in the sudoers file` と出る。出ていたのは
「パスワードが要る」なので、**載ってはいた**。

### A/B にしたのに「入れ直してください」と言っていた

1.5.13 でルートを A/B にして、入れ直さずにシステムを丸ごと
入れ替えられるようにした。ところが設定の Update タブは、その仕掛けを
知らないままだった。

```
Kernel is current. 1.5.15 changes need a reinstall.
```

仕掛けは出来ているのに、画面がそこへ案内していない。使えないのと同じ。

**Update タブが `myos-update status` の `system` を見るようにした。**

| ルートの形 | 出るもの |
| --- | --- |
| A/B | **Update system** の釦。使っていないほうへ入れて起動先を切り替える |
| 1 本 | 今までどおり「入れ直しが要ります」 |

カーネルとシステムの両方が古いときは釦が 2 つ並ぶ。押す順は
文言で示す (システム → カーネル)。釦の並びは 1 箇所で決めるようにした。
描くところと当たり判定で別々に数えると、片方だけ直したときにずれる
(Add Programs で実際にやった)。

## 1.5.15 で直したもの

### 初回セットアップの Cancel が、中途半端な机を出していた

1.5.14 で ESC の出口は塞いだが、残した Cancel の行き先が
おかしいままだった。押すと **root のままデスクトップが出る**。

これは「使う人を作らずに終わったら、直せる画面を出す」という
逃げ道のつもりで置いてあった。しかし初回起動でこれを押した人が
欲しいのは、直せる画面ではなく**やり直し**である。root の机に
着いても、そこから初回セットアップをやり直す道は用意されていない。

**Cancel を Shut down にした。** 押すと電源が落ちる。

| | |
| --- | --- |
| 釦の名前 | Cancel → **Shut down** |
| 押したとき | 電源が落ちる (`myos-poweroff`。X も畳んで、時計も書き戻す) |
| 次に電源を入れると | **また初回セットアップから始まる** |

やり直せるのは、成功したときにしか `/etc/myos/setup-done` を
置いていないため。Cancel では置かないので、次の起動でまたここに来る。
この作りは元からそうなっていて、変えたのは「抜けたあとどうするか」
だけ。

名前も変えた。**「取り消し」の顔をして機械を止める釦は罠**でしかない。
押す前に何が起きるか読めるようにしておく。最初の画面にも
「Shut down turns the computer off; Setup runs again the next time.」と
出している。

root のまま出す道は残してあるが、これはセットアップが途中で死んだとき
専用になった。狙って踏める場所には無い。

## 1.5.14 で直したもの

### 初回セットアップが ESC で抜けられてしまった

抜けられる作り自体は意図的だった。使う人を作らずに終わった場合は
root のままデスクトップを出す。**何も出来ないより、直せる画面が出る
ほうがいい**という判断で、逃げ道を残してある。

問題は **ESC が事故で押せる**こと。指が滑っただけで root の机に
着いてしまう。代償の重い出口が、押しやすい場所に置いてあった。

**ESC では抜けないようにした。** 逃げ道は Cancel のボタンに残す。
あれは狙って押すものなので、事故では踏まない。

| | |
| --- | --- |
| ESC を 5 回 | **抜けない** (画面もそのまま) |
| Cancel を押す | 今までどおり抜ける |

出口を無くさずに、事故だけを防ぐ。**代償の重い操作は、それなりの手間の
先に置く**という考え方は、Ctrl+Alt+Del で重要なプロセスを止めるときの
確認と同じ。

## 1.5.13 で入れるもの

### システムをまるごと入れ替えられるようにした (ルート A/B)

`myos-update` はカーネルしか入れ替えられなかった。**直る頻度が高いのは
GUI 側のほう**で、実際 1 日で 5 個直っている。それが届かない。

カーネルでやっていることを、そのままルートにも広げた。

```
p1  256M   生の起動領域 (カーネル A/B。今までと同じ)
p2  swap
p3  root A
p4  拡張区画
    p5  root B   (root A と同じ大きさ)
    p6  home     (残り全部、共有)
```

更新の流れ:

1. `myos-root-X.squashfs` を落とす
2. 照合する
3. **使っていないほうのルート**を空けて展開する
4. ペイロードテーブルの `root=` を書き換える

3 の途中で電源が落ちても、**いま動いている側は無傷**。4 のあとで新しい
側が起動しなければ、**起動中に `R`** を押せば控え (LBA 21) のテーブルで
立ち、古いルートに戻る。

**新しい戻り道は作っていない。** カーネルのために用意した A/B と `R` が、
そのままルートにも効く。

### home を分けた理由

ルートを入れ替えると、古いルートの中にあった自分のファイルが置き去りに
なる。毎回コピーするのは遅いし、途中で落ちたときに失う。**共有の区画に
出すのが唯一まともな答え**で、Android も ChromeOS もそうしている。

`myos-init` に `/home` のマウントを足した。今までは `swapon -a` しか
していなかったので、区画を分けても見えないままだった。

### 入れ替えても引き継ぐもの

squashfs は**作った人の機械のもの**なので、そのまま置くと設定が合わない。
入れた機械に属するものだけ写す。

```
etc/fstab                 区画の名前
etc/myos/boot.conf        ディスクと生領域の場所
etc/adjtime / localtime   時計の扱いと地域
etc/default/keyboard      キーボードの配列
etc/myos/login.conf       使う人
```

初回セットアップは**やり直させない**。使う人を作り直すと、`/home` の
中身と食い違って別人になってしまう。

### 小さいディスクでは A/B にしない

ルート 1 本 8GB を狙い、入らなければ 6GB まで縮める。それでも入らなければ
**A/B を諦めて今までどおり 1 本**にする。

16GB のディスクで 4.7GB ずつに割るより、13GB の 1 本のほうが日々使い
やすい。更新の便利さと、そもそも使えることを秤にかけて後者を採る。

| ディスク | |
| --- | --- |
| 8GB | 1 本 (6.5GB) |
| 16GB | 1 本 (13GB) |
| 20GB | A/B (6.5GB x2 + home 4GB) |
| 32GB | A/B (8GB x2 + home 11GB) |
| 120GB | A/B (8GB x2 + home 99GB) |

A/B が無い機械で `apply-system` を叩くと、**何も壊さずに断る**。

### 区画の切り方

MBR の基本区画は 4 つまで。起動領域・スワップ・ルート A で 3 つ使うので、
残り 1 つを拡張区画にして中にルート B と home を置く。論理区画は基本
区画がいくつあっても**必ず 5 から**数える (スワップの有無で番号がずれ
ないことを実際に切って確かめた)。

カーネルは区画を見ずに生 LBA で読むので、**ブートローダーには何の影響も
無い**。

## 1.5.12 で入れるもの

### 音をどこから出すか選べるようにした (設定に Sound タブ)

実機で音が出なかった。HDMI のモニタ内蔵スピーカーで聞きたいのに、
既定の出口がマザーボードの緑の穴 (何も挿していない) になっていた。

原因は **myOS 自身の決め打ち**。起動時にこうしていた。

> HDMI が既定になっていたらアナログへ寄せる

実機でよくある「音が出ない」を潰すつもりの処理だったが、**HDMI で
聞きたい人には完全に裏目**。どちらが正解かは機械ごとに違うので、
こちらで決めてはいけなかった。

決め打ちをやめて、**選べるようにした**。

### 繋がっていないものは出さない

PulseAudio はポートごとに `available` を持っている。挿さっていない
穴は `no` になるので、そこを見て落とす。

| | |
| --- | --- |
| `available: yes` | 挿さっている。**出す** |
| `available: no` | 挿さっていない。**出さない** |
| `available: unknown` | コーデックが判別できない。**出す** |

`unknown` を隠さないのが肝。古いコーデックはジャック検出を持たない
ことがあり、そこを隠すと**唯一の出口が消えて何も選べなくなる**。

同じ理由で、**全部 `no` だったときは全部出す**。選べるものが無い画面を
出しても、使う人には打つ手が無い。「出しても鳴らないかもしれない」
ほうが、「何も選べない」よりまし。そういうものには
`(not detected)` と添える。

### プロファイルが off の HDMI も拾う

HDMI はカードのプロファイルが `off` だと sink が存在しない。実機でも
そうなっていて、`pactl set-default-sink` は
「そのようなエンティティはありません」で弾かれていた。

ポートの一覧と `available` はプロファイルと無関係に出るので、
**「挿さっているが今は使えない出口」**を見つけられる。選ばれたときに
プロファイルごと切り替える。

```
set-card-profile alsa_card.pci-0000_01_00.1 output:hdmi-stereo
set-sink-port    alsa_output.hdmi hdmi-output-0
set-default-sink alsa_output.hdmi
move-sink-input  7 alsa_output.hdmi        <- 鳴っているものを連れて行く
```

最後の 1 行が要る。既定を変えただけでは**もう鳴っているものは移らない**。
ここを忘れると「切り替えたのに音が変わらない」になる。

選んだものは `~/.myos/audio.conf` に控えて、次の起動で復元する。

### 実装は別のコマンドに切った

一覧も切り替えも `myos-audio` という道具に任せて、設定の画面はそれを
呼ぶだけにした。出口の見つけ方が地味に込み入っているので、画面の都合と
混ぜたくなかった。単体で試せる。

```
myos-audio list        出せる出口を並べる
myos-audio set <id>    そこへ切り替える
```

`pactl` の出力は日本語環境だと項目名まで翻訳される。読み取る側が壊れる
ので `LC_ALL=C` で呼んでいる。

### `/dev/root` を起動時に張る

1.5.11 で `myos-setres` が名前に頼らないようにしたが、**それだけでは
片手落ち**だった。

`/dev/root` という名前は、カーネルが `root=` でそのままマウントした
ときに `/proc/mounts` へ出てくる。myOS は initramfs に `/init` を
置かない作りなので、必ずこの道を通る。ところが**そんなデバイス
ファイルは存在しない**。

道具の側で名前を見ないようにしても、

- `df` と `mount` の表示は `/dev/root` のまま
- ここを見に行くものが他にもあれば、また同じことが起きる

**張っておくのが筋。** PID 1 でルートを読み書き可にした直後に、
実体へのリンクを作る。

場所は `/proc/self/mountinfo` の 3 列目 (`major:minor`) から引く。
名前ではなく番号なので、そこに `/dev/root` と書かれていようが関係
ない。

```
27 1 254:0 / / rw,relatime - ext4 /dev/vda rw
       ^^^^^ ここ
```

向ける先は**パーティション** (`sda2` など)。ルートはディスクそのもの
ではないので、意味のとおりに張る。`myos-setres` はデバイス番号から
引くので、この向き先には依存しない。

## 1.5.11 で直したもの

実機に入れて動かしたら、続けて 2 つ出た。どちらも「実機でしか出ない」
類ではなく、**QEMU では条件が揃わなかっただけ**のもの。

### 解像度を変えられなかった (`/dev/root がありません`)

設定で解像度を選ぶと「パスワードが違う」と出る。正しいパスワードを
入れているのに。端末から直接叩いて、本当の理由が出た。

```
C:\home\manh> sudo myos-setres 1920 1080
myos-setres: /dev/root がありません
```

`myos-setres` は `/proc/mounts` を読んでルートのディスクを割り出して
いた。ところがカーネルが `root=` でそのままマウントすると、そこに
出てくる名前は **`/dev/root`** で、**実体のファイルが無い**。

名前を当てにするのをやめて、**デバイス番号**から引くようにした。

```
ルートの st_dev -> major:minor -> /sys/dev/block/M:m -> 実物
```

これなら名前が何であろうと行き着く。`sda2` でも `nvme0n1p2` でも
`mmcblk0p1` でも、パーティションではなくディスクそのものでも、同じ道で
解ける (5 通り並べて確かめた)。

### 「パスワードが違う」が、本当の理由を握り潰していた

上の件で一番たちが悪かったのはここ。`myos-runas` はこう書いていた。

```c
/* sudo は認証に失敗すると 1 で終わる。 */
return WIFEXITED(st) && WEXITSTATUS(st) != 1;
```

**sudo の認証失敗も、起動したコマンドの失敗も、どちらも終了コード 1。**
区別が付いていない。だから `myos-setres` が転んだだけなのに
「Wrong password, or you are not an administrator.」と出て、
`/dev/root がありません` はどこにも表示されなかった。

**使う人が原因に辿り着けない。** 直すべきはこちらが先だった。

2 段に分けた。

| 段 | やること | ここでの失敗の意味 |
| --- | --- | --- |
| 1 | `sudo -S -k -v` | **パスワードが違う** |
| 2 | `sudo -n <コマンド>` | **コマンドの都合** |

`-v` は認証して時刻印を更新するだけで何も起動しない。2 段目の `-n` は
その時刻印を使うので、二度聞かれることはない。

2 段目で転んだときは、**そのコマンドが最後に言い残した 1 行**を画面に
出す。「The command could not run:」の下にそのまま並ぶ。

### Setup を F3 でやめると、意味の分からない画面が残っていた

## 1.5.9 で入れたもの

### ブートセクタに BPB の場所を明け渡した

USB メモリから起動するとき、BIOS の中には**ブートセクタには BPB
(BIOS Parameter Block) があるはずだと決めつけて、そこへ media の
ジオメトリを書き込んでから制御を渡す**ものがある。書き込む先は

```
0x18  1 トラックあたりのセクタ数
0x1A  ヘッド数
0x1C  隠しセクタ数
```

あたりが中心で、全域 (0x0B-0x3D) を書き換えるものもある。

myOS の Stage1 はそこにコードを置いていた。つまり **起動する前に
自分のコードを壊される。** CD (El Torito) では起きないので、USB で
だけ出る。しかも症状は「何も起きない」なので原因が見えない。

### syslinux はどうしているか

Alpine と Debian の ISO の先頭 512 バイトを実際に読んで、逆アセンブル
した。

```
0x00  33ED    xor bp,bp
0x02  90      nop
 ...          (0x1F まで全部 NOP)
0x20  33ED    xor bp,bp      <- 本体はここから
```

**BIOS が触る 0x18-0x1F を NOP 帯にしてある。** 踏まれてもそのまま
滑って 0x20 の本体に着く。うまい。

ただしこれは全域 (0x0B-0x3D) を書き換える BIOS には勝てない。0x20 から
0x3D までの本体が消える。

### myOS はもう一歩固くした

FAT のブートセクタと同じ形にして、**0x03-0x3D を丸ごと明け渡す**。

```
0x00  EB 3C   jmp short 0x3E
0x02  90      nop
0x03-0x3D     全部ゼロ (BIOS の書き込み先)
0x3E          ここからコード
```

先頭で飛び越すので、そこに何を書かれても関係ない。全域を書き換える
BIOS にも耐える。

中身は 0 のままにして、**FAT だと名乗らない**。ここに本物らしい BPB を
置くと、BIOS によっては「フロッピーだ」と判断して FDD エミュレーション
を選ぶ。こちらはパーティションテーブルを持っているので、ハード
ディスクとして扱ってもらったほうが都合がよい。

### 効くことを確かめた

「BIOS が BPB を書き込んできた」状況を人の手で再現して、直す前と
後を並べた。LBA 0 の 0x0B-0x3D に、BIOS が書きそうな BPB を流し込む。

| Stage1 | BPB を書き込まれたあと |
| --- | --- |
| BPB 域にコードがある (1.5.8 まで) | **完全に死ぬ。シリアルに一文字も出ない** |
| BPB 域を空けた (1.5.9) | **普通に起動する** |

QEMU の SeaBIOS は BPB を書かないので、**普通に動かしているだけでは
絶対に出ない故障**だった。作って壊してみて初めて見える。

CD とディスクの両方で退行していないことも確認済み。

## 1.5.7 / 1.5.8 で直したもの

### MBR の書き方が、実際に起動している hybrid ISO と違っていた

1.5.6 の USB 起動が実機 (GA-H81M-D3V-JA) で動かなかった。切り分けの
結果、**媒体は完璧に書けていた**ことが分かった。Windows から USB の
生セクタを読むと、ビルドしたものと 1 バイトも違わない。

```
LBA0  sig=55AA  boot=80  chs=00 02 00  type=83
LBA1  = 'MYS2'
LBA20 = 'MYOSPLD2'
```

BIOS も USB 自体は見えていた (`Peripherals` の `USB Storage Devices`
に出る)。それでも起動候補に出ない。つまり **BIOS がこの MBR を
「起動できるディスク」と認めていない**。

推測で直すのをやめて、**実際に世に出ている hybrid ISO の先頭 512
バイトを読んだ**。Alpine と Debian、どちらも同じ書き方だった。

| | Alpine | Debian | myOS 1.5.6 |
| --- | --- | --- | --- |
| 起動フラグ | 80 | 80 | 80 |
| **種別** | **00** | **00** | **83** |
| **開始 CHS** | **00 01 00** | **00 01 00** | **00 02 00** |
| 開始 LBA | 0 | 0 | 0 |
| **終了 CHS** | **3F 20 D0** | **3F A0 76** | **FE FF FF** |

3 箇所ずれていた。

**終了 CHS から、isohybrid が使っているジオメトリが逆算できた。**
`head` の上限が 63、`sector` が 32 なので **64 ヘッド x 32 セクタ**。
ディスクの実際の形とは関係のない、ただの取り決め。myOS は 255x63 で
計算していた。

その式で Alpine (428032 セクタ) と Debian (1292288 セクタ) の終了 CHS
を計算し直すと、**どちらも公開されている値と完全に一致**した。読みが
正しいことの裏付けになる。

種別 `0x00` は本来「空き」の意味だが、isohybrid はそう書いていて、
それで実機が起動している。Linux は ISO9660 のほうを読むのでこの欄は
見ていない。**実績のある書き方に完全に揃えた。**

ビルドのたびに開始 CHS が `00 01 00` であることも検査する。

### 元の間違いの出どころ

CHS の値は `build_image.py` から写した。あちらはパーティションが
LBA 2048 から始まる作りで、CHS は「LBA を使うので便宜的な値」として
置いてあった。**意味を確かめずに、LBA 0 から始まる別の用途へ持って
きた。**「動いているコードから写す」が安全とは限らない、という例。



1.5.6 で足した MBR に、辻褄の合わないところがあった。

### 分かっていること

CD とディスクの両方で起動することは QEMU で確認済み (退行なし)。

**ただし、これで実機が起動するようになるとは限らない。** 確かめ
られたのは「実績のある書き方と 3 箇所違っていた」ことまでで、
その違いが H81 の BIOS の判断を変えるかどうかは実機でしか分からない。

## 1.5.6 で入れたもの

### 1 枚の ISO が CD からも USB からも起動するようになった

今までの ISO は **El Torito の CD 専用**で、USB メモリに書いても起動
しなかった。Rufus に渡すと「非対応のイメージです」と断られる。実際に
出来上がった ISO の先頭を読むと、理由がそのまま出ている。

```
オフセット 510      : 0000     <- MBR の署名 (55AA) が無い
パーティションテーブル : 全部ゼロ
先頭 32KB           : 全部ゼロ
```

**この「全部ゼロの 32KB」が答えでもあった。** ISO9660 は規格で先頭 32KB
を「システム領域」として丸ごと空けてあり、xorriso も何も書かない。
ここにディスクとして起動するための入口を置けば、CD 側の仕掛けとは
一切重ならない。

```
LBA 0-17   Stage1 + Stage2 (/boot/boot.img と同じ中身)
LBA 20     ペイロードテーブルの写し
```

### Stage1 も Stage2 も直していない

ブートローダーには一行も手を入れていない。**元から両方に対応できる形に
なっていた**ことが、読み返して分かった。

**Stage1** は 0x7E00 に `MYS2` の目印があれば読み込みを飛ばす。CD では
BIOS が 18 セクタまとめて載せてくれるので飛ばし、USB では 1 セクタしか
載らないので自分で LBA 1-17 を読む。分岐は既にあった。

**ペイロードテーブルの中の LBA** は、もともと「ISO の先頭からの 512
バイト単位の絶対値」で入っている。出荷済みの 1.5.5 の ISO を実際に
読んで確かめた。

```
setup LBA 160 x 512        = 81920 バイト
cd_ptbl_lba 39 x 2048 + 2048 = 81920 バイト   <- 一致
```

CD では `disk_read` が 4 で割って 2048 バイト単位に直し、ディスクでは
そのまま使う。**同じ 1 枚のテーブルが両方で正しい。** だから写しを
置くだけで済んだ。

Stage2 は「テーブルはどこか」を CD 用 (`cd_ptbl_lba`) とディスク用
(`PTBL_LBA = 20`) で切り替え、外したらもう一方も試す。両方に置いて
あれば必ず当たる。

### 確かめ方

同じ 1 本の ISO を QEMU で 2 通りに繋いで、対照実験を 2 つ添えた。

| ISO | 繋ぎ方 | 結果 |
| --- | --- | --- |
| 完成品 | CD | カーネル起動 (**退行なし**) |
| 完成品 | ハードディスク | **カーネル起動** |
| システム領域を消したもの (= 1.5.5 まで) | ハードディスク | `Boot failed: not a bootable disk` |
| Stage1+Stage2 だけ置き、LBA 20 の写しを消したもの | ハードディスク | `Payload tbl : NOT FOUND` → Halted |

下 2 つが対照実験で、**足した 2 つがどちらも要る**ことを示している。
片方だけでは起動しない。

ビルドの最後に、この形になっているかを毎回検査する (先頭の 0x55AA、
LBA 1 の `MYS2`、LBA 20 のテーブルが元と 1 バイトも違わないこと、
起動可能フラグ、そして **ISO9660 の `CD001` を壊していないこと**)。

### 分かっていること

- **インストーラが USB を媒体として見つける経路は、実機で未確認。**
  initramfs は元から `/dev/sda` を iso9660 で開こうとするので通るはず
  だが、通しで動かしたわけではない
- QEMU (SeaBIOS) でハードディスクとして起動すると、画面に
  `Boot medium : CD-ROM` と出る。BIOS が CD だと誤って答えるためで、
  Stage2 は自分で気づいて読み直すので**起動には影響しない**。実機の
  BIOS では正しく出ることが多い

## 1.5.4 で直したもの

1.5.3 で入れたカーネルの更新に、出す前に気づいた穴が 2 つあった。
どちらも「一度でも動かせば分かる」ものではなく、次にカーネルを
作り直した版を出したとき初めて牙を剥く類のものだった。

### 版の数字で更新するかを決めていた

`z` を上げた版は、決めのとおり**カーネルを作り直していない**。中身は
1 バイトも違わない。それなのに版の文字列だけを見比べていたので、
`1.5.3` と `1.5.4` が違うというだけで「新しいのがある」と言い、21MB を
落として生領域を書き換えていた。書き込みには必ず危険が伴うのに、
得るものが何も無い。

比べる相手を実物の sha256 に変えた。

| | |
| --- | --- |
| いま乗っているもの | `myos-writeboot --kernel-sha` が生領域から読み直して数える |
| 出ているもの | リリースの `.sha256` (92 バイト)。本体を落とす前に取れる |

読み直すのが肝で、「入れたときの値」を控えておく作りにはしなかった。
控えは書き換え忘れや書き損じで実物とずれる。ずれた控えを信じると、
**入れ替えたのに入れ替わっていない**のを見落とす。生領域を読めば
ずれようが無い。setup 部はセクタ丁度に収まり、本体のバイト数は
テーブルに入っているので、繋げると元の bzImage と完全に一致する。

副産物として、版の数字が同じでもカーネルの中身が違う機械 (書き損じ、
作りかけを焼いた) を見つけられるようになった。前の作りでは、こういう
機械こそ直したいのに「最新です」と言って何もしなかった。

### 版の数字が嘘になっていた

`myos-update` が入れ替えるのはカーネルと initramfs だけで、GUI も
インストーラも `/usr` の中身もそのまま残る。それなのに更新のあと
`version.conf` の版を新しい数字に書き換えていた。

つまり **「1.5.4 です」と名乗りながら、1.5.4 で直した GUI の不具合を
全部抱えている機械**が出来上がる。次に不具合の報告を受けたとき、
版番号を信じると原因に辿り着けない。

`version` は入れたときの ISO の版として据え置き、カーネルの版は
`kernel` として別に持つことにした。設定の Update タブも二段になる。

```
System:     1.5.3
Kernel:     1.5.4
Available:  1.5.4
```

カーネルは最新だが本体の版のほうが古い、という組み合わせのときは
「カーネルは最新。1.5.4 の変更には入れ直しが要る」と出す。黙って
「最新です」と出すと、Update を押しても何も起きない理由が分からない。

なお `kernel` の行はただの見出しで、入れ替えるかどうかの判断には
使わない (判断は上のとおり sha256)。だから書き損じても表示が古く
なるだけで、動きは壊れない。**表示は間違えても直せるが、判断を
間違えると生領域を壊す。**間違えていい側とそうでない側を分けてある。

### そのほか

- 設定の Update タブで **Add Programs の押せる場所が 18 ピクセルずれて
  いた**。表示を三段にしたぶん下がったのに、押した場所を調べる側の
  積み方を直していなかった

## 1.5.3 で入れたもの

### カーネルを入れ替えられるようにした

インストールしたあとカーネルを上げる手段が無かった。入れ直すしかなく、
中のものは全部消えていた。設定の **Update** タブから入れ替えられる。

生領域は 256MB あるのに使っているのは 57MB ほど。半分ずつに区切って
**2 つの置き場**として使い、入れ替えるときは「いま使っていないほう」へ
書く。書く順番が肝心で、

1. 使っていないほうへカーネルと initramfs を書く
2. 読み返して、確かに乗ったことを確かめる
3. いまのペイロードテーブルを控え (LBA 21) へ写す
4. 最後にテーブル (LBA 20、1 セクタ) を差し替える

3 より前で電源が落ちても、古いテーブルが古い置き場を指したままなので
次の起動は今までどおりになる。

**本当に危ないのは書き込みの中断ではなく「新しいカーネルがその機械で
動かない」ほう。** 起動しなくなると手が出せない。そこで、
**起動中に `R` を押しっぱなしにすると 1 つ前のカーネルで立つ**。
生領域に古いカーネルの実体も残っているので、本当に戻れる。

カーネルはリリースに単体でも置いてある (21MB)。sha256 を突き合わせて
から書くので、途中で壊れたものが生領域に入ることはない。

解像度の希望とコマンドラインは入れ替えても引き継ぐ。

### 設定に Update タブ

カーネル・Debian のセキュリティ更新・アプリの追加を 1 箇所にまとめた。
どれも「網に繋がっていないと何も出来ない」点は同じなので、
別々の画面に散らすより分かりやすい。

### `modprobe` が組み込みドライバを認識する

`.ko` は 1 つも無い (全部 `=y`) が、`/lib/modules` が存在しないせいで

```
$ modprobe ext4
modprobe: FATAL: Module ext4 not found in directory /lib/modules/6.12.9
```

## 1.5 で入れたもの

### スワップ

インストーラがこれまで生領域とルートしか作っておらず、スワップを
1 バイトも用意していなかった。入れる相手は Core 2 Duo 世代 (2006-) の
実機なので、メモリ 1GB や 2GB の機械が普通にある。そこで Firefox を
開くと OOM killer が走り、前触れなくアプリが消える。「重い」ではなく
「壊れた」に見える壊れ方だった。

大きさはメモリと同じだけ。ただし 4GB で頭打ち、ディスクの 15% まで、
ルートには 3GB 残す。取れないなら作らない。

| ディスク | メモリ | スワップ |
| --- | --- | --- |
| 3 GB | 1 GB | 無し |
| 4 GB | 1 GB | 614 MB |
| 8 GB | 2 GB | 1228 MB |
| 40 GB | 16 GB | 4096 MB |

### 時刻合わせ

本体の時計は放っておくと月に何分もずれる。ずれた時計は
「証明書がまだ有効でない」で HTTPS が全部落ちるという、原因の
まるで分からない壊れ方をする。chrony を入れて、起動して網が
上がったあとに合わせるようにした。合わせた時刻は電源を切るときに
本体の時計へ書き戻す。

`rtcsync` は使わない。あれは必ず UTC で書くので、RTC をローカル時刻
として扱う myOS の決めと食い違い、起動のたびに 9 時間ずれる。

### タスクマネージャが自分で更新する

`R` を押すまで表示が止まったままだった。CPU の割合は前回との差で
出す作りなので、開いた直後は必ず全部 0% になっていた。1 秒ごとに
数え直す。

## 1.4 で入れたもの

### タスクマネージャ

`Ctrl+Alt+Del` で出てくる。Windows 98 の「プログラムの強制終了」と
NT 系のタスクマネージャを足して 2 で割ったもの。

| タブ | 中身 |
| --- | --- |
| Applications | 開いている窓。まず `WM_DELETE_WINDOW` で頼み、受け付けない窓は `XKillClient` で切る |
| Processes | `/proc` から。CPU の割合 / 常駐メモリ / 持ち主。End Process は `SIGTERM`、Force End は `SIGKILL` |

CPU の割合は前回との差で出す。累計を割合として出すと、ずっと動いている
ものが常に上位に居座って役に立たない。PID 1 は殺すとカーネルパニックに
なるので断る。

作るにあたって、自作のウィンドウマネージャに `WM_STATE` を付けさせた。
窓を枠で包み直す (reparent) 作りなので、これが無いと外から中身の窓を
見つける手掛かりが無い。付けるまでは窓が 1 つも見えなかった。

### デバイスマネージャー

何が刺さっていて、そのうちどれにドライバが当たっているかを見る。
見た目のためではなく切り分けのため。「音が出ない」「無線が繋がらない」
と言われたときの原因は 3 つあって、対処がまるで違う。

1. そもそも機器が見えていない
2. 見えているがドライバが当たっていない
3. ドライバは当たっているがファームウェアが無い

症状はどれも同じ「動かない」になる。ドライバの無い機器と
ファームウェアの足りない機器には黄色い「!」を付ける。

`lspci` も `pci.ids` も入れない (`pci.ids` だけで 1MB 超、CD に収まらない)。
ベンダー名はよく見るものだけ内蔵の表から出し、機種名の代わりに PCI の
クラス名を使う。Windows 9x が知らない機器に付けていたのと同じ形になる。

### JP キーボードを選んでも英語配列になる

`@` を押すと `[` が出る、という形で出ていた。原因が 3 つ重なっていた。

1. セットアップが書く `xorg.conf.d/10-keyboard.conf` は、次に X が起動する
   まで効かない。書いた直後のセッションはずっと `us` のまま
2. fcitx5 の xcb モジュールは既定で自分の配列を X に押し付ける。しかも
   初回起動時の X の配列を自分の既定として憶えるので、1 のせいで `us` を
   憶えると以後 X 側を `jp` にしても毎回戻される
3. インストールディスクの live 環境に配列の設定が無かった

配列は X が持ち、fcitx5 は変換だけをやる、と決めた。セットアップは
設定を書いたあと `setxkbmap` で今の X にも即座に効かせる。

### インストール後にディスクが排出されない

排出できないのが当たり前だった。live 環境はディスクの中の squashfs を
root にして動いているので、動いている間はドライブがふさがっている
(`CDROMEJECT` は開いている数が 1 でないと `EBUSY` を返す)。
レガシー BIOS には起動順を変える口も無い。

排出を諦めて、入れっぱなしでも困らないようにした。ペイロードテーブルに
「インストール用の媒体」の印を足し、Stage2 は自分にその印があるとき
他のディスクを探して、インストール済みの myOS があればそちらを起動する。
もう一度セットアップしたければ 5 秒のあいだに `I` を押す。

## 1.2 で入れたもの

**GPU のファームウェアを起動時に渡すようにした。**

`.ko` を全て `=y` にしてある副作用で、PCI の probe がルートのマウントより
先に走っていた。実測するとこうなる。

```
[    1.863217] calling  radeon_module_init  @ 1
[    1.863637] calling  amdgpu_init         @ 1
[    2.993505] VFS: Cannot open root device
```

1.1 秒の差がある。この間 `/lib/firmware` は存在しないので、ファームウェアを

展開されるので probe に間に合う。中身は 1 ファイルずつ zstd に潰してあり
(`CONFIG_FW_LOADER_COMPRESS_ZSTD`)、110MB が 35MB に収まる。

| --- | --- | --- |
| Radeon HD 2000〜HD 7000 / R9 200・300 | **真っ暗** | 表示 + 3D (`r600` / `radeonsi`) |
| Radeon RX 400・500 / Vega / RX 5000〜7000 | **真っ暗** | 表示 + 3D + Vulkan (`radeonsi` / RADV) |
| GeForce GTX 9xx / 10xx / 16xx / RTX 20xx | 表示のみ | 表示 + 3D (`nvc0`。クロックは上がらない) |
| Intel | 表示 + 3D | 同じ (DMC が読めるので消費電力と表示が安定) |

## 使い方

### CD に焼く

```
# Linux
wodim dev=/dev/sr0 -v -sao myos-install-1.0.iso

# Windows / macOS
イメージを右クリック → 「ディスクイメージの書き込み」
```

### USB メモリに書く

同じ ISO がそのまま USB でも使える。

```
sudo dd if=myos-install-1.0.iso of=/dev/sdX bs=4M status=progress conv=fsync
```

`/dev/sdX` は書き込み先の USB メモリ。**間違えると中身が消える**ので
`lsblk` で必ず確認すること。

### 入れる

1. CD / USB から起動する
2. 青い画面でインストール先のディスクを選ぶ
   - ディスクを丸ごと消す / 空き領域に入れる のどちらかを選ぶ
   - **F8 を押すまで何も書き込まない**
3. コピーが終わると自動で再起動する
4. 再起動後にユーザー名・パスワード・キーボード配列・タイムゾーンを決める

## 必要なもの

| 項目 | 条件 |
| --- | --- |
| CPU | x86_64（Core 2 Duo 世代 / 2006年以降） |
| ファームウェア | **レガシー BIOS**（UEFI は対象外） |
| メモリ | 1 GB 以上（Firefox を使うなら 2 GB） |
| ディスク | 2.5 GB 以上（推奨 8 GB。4 GB を割るとスワップを作らない） |
| 起動メディア | CD-R、または 1 GB 以上の USB メモリ |

UEFI しかない機械では起動しない。BIOS の設定に CSM / Legacy Boot が
あれば、それを有効にする。

## 入っているもの

- デスクトップ（ウィンドウマネージャ / タスクバー / スタートメニュー）
- ファイルマネージャ、メモ帳、画像ビューア、設定、MS-DOS プロンプト
- 閲覧ソフト（ディスクには入っていない。初回に選んで入れる）
- Java 17（JRE）
- ClamAV（定義入り。オフラインでも検査できる）
- ufw（起動時に有効。入ってくる通信は既定で断る）
- OpenSSH サーバー（既定では停止。`myos-ssh on` で開始）
- Python 3

`apt` がそのまま使えるので、Debian のパッケージを後から入れられる。

```
sudo apt update
sudo apt install gimp vlc gcc
```

## 画面が出ないとき

起動中に **S を押しっぱなし**にすると、GPU のドライバを使わずに
起動する（セーフグラフィックス）。画面は必ず映るが、描画は CPU が
行うので 3D は遅くなる。

既定では GPU のドライバ（`i915` / `amdgpu` / `nouveau`）を使う。
実機で 3D を実用速度で動かすにはこれが要る。相性で画面が出ない
機械に当たったときの逃げ道が S。

## 画面の解像度

設定 → **Display** で選ぶ。**反映には再起動が要る。**

解像度はブートローダーが VBE で決める。X からは変えられないので、
「次に起動するときの希望」をディスクに書いて再起動する形になる。
Windows 98 も色深度の変更には再起動が要った。

選んだ解像度がその画面で出せない場合は、出せるものに自動で落ちる。
起動しなくなることはない。

端末からは `myos-setres` でも変えられる。

```
myos-setres              # いまの設定
myos-setres 1280 1024    # 次回から
myos-setres auto         # おまかせに戻す
```

## 操作

見た目は Windows 98、キー操作は今の Windows に寄せてある。

| キー | 動作 |
| --- | --- |
| `Alt+Tab` / `Alt+Shift+Tab` | ウィンドウの切り替え |
| `Alt+F4` | 閉じる |
| Windows キー | スタートメニュー |
| `Win+E` | ファイルマネージャ |
| `Win+D` | デスクトップの表示 |
| `Win+←` / `Win+→` | 画面の左右半分にスナップ |

## 仮想環境で試す場合

VirtualBox / VMware などで動かすときは、ここを間違えると
**動いているのに画面が真っ黒**になる。どちらも実際に踏んだ。

| 設定 | 値 | 外すとどうなるか |
| --- | --- | --- |
| ファームウェア | **BIOS**（UEFI は不可） | そもそも起動しない |
| OS タイプ | **64bit のもの** | CPUID からロングモードが消され、カーネルが無言で停止する |
| グラフィックス | どちらでもよい | 1.1.1 以降は `vmwgfx` だけを止めるので VMSVGA でも映る |
| メモリ | 2 GB 以上 | インストーラが 512 MB の tmpfs を使うので 1 GB では足りない |

64bit でない場合は Stage2 が理由を画面に出して止まる。

それでも画面が出ないときは、起動中に **S を押しっぱなし**にする。
GPU のドライバを一切使わない状態で立ち上がるので、必ず映る。

Hyper-V は**第 1 世代**で作ること。第 2 世代は UEFI 専用。

## 分かっている制限

- **UEFI では起動しない。** レガシー BIOS 専用
- `.java` のコンパイルと `.c` のその場実行はできない
  （CD-R に収めるため javac と gcc を外した。`apt install` で戻せる）
- systemd を使っていないので、デーモンを自動起動するパッケージは
  `/myos-init` に起動行を自分で足す必要がある
- 「空き領域に入れる」を選んだ場合、MBR は myOS のものに置き換わる。
  既存 OS のデータは残るが、そのままでは起動しなくなる
- GPU が無い環境では 3D はソフトウェア処理になり、実用速度は出ない

## 作り直す

```bash
# 1. ルートファイルシステム (debootstrap から。1 回目は 30 分ほど)
sudo tools/build_rootfs.sh

# 2. カーネル (.ko を全て =y にしたモノリシック構成)
sudo tools/build_kernel.sh

# 3. インストーラの initramfs
sudo tools/make_install_initramfs.sh

# 4. ルートを固める
sudo mksquashfs /home/user/rootfs build/myos.squashfs \
     -comp zstd -Xcompression-level 19 -b 1M -noappend

# 5. ISO
sudo python3 tools/build_iso.py \
     --kernel  ../kernelbuild/linux-6.12.9/arch/x86/boot/bzImage \
     --initrd  build/install-initramfs.cpio.gz \
     --payload build/myos.squashfs
```

## 確かめたこと

QEMU 上で、CD から入れて再起動するところまで通してある。

| 段階 | 結果 |
| --- | --- |
| CD から起動 (El Torito, ノーエミュレーション) | Stage2 が CD を認識、2048 バイトセクタで読む |
| initramfs がメディアを探す | `/dev/sr0` を見つけて squashfs をマウント |
| 青いテキスト画面 | ディスク一覧 → 入れ方 → 確認 |
| パーティションとフォーマット | 128 MB の生領域 + ext4 のルート |
| GUI のコピー | 1.7 GiB を展開、進捗が進む |
| ブートローダーの書き込み | MBR / Stage2 / ペイロードテーブル / カーネル |
| 再起動して installed から起動 | `/dev/sda2` を ext4 で read-write マウント |
| 初回セットアップ | 「myOS Setup - Step 1 of 5」が出る |
