# 動作確認の方法

## 1. QEMU による自動検証（推奨・普段づかい）

```bash
make run          # 起動して 2 秒後の画面を取得
make run-keys     # キー入力を送り込んでから取得
```

`tools/run_qemu.py` は QEMU のモニタ機能を使って次のことをする。

- `pmemsave 0xB8000 4000` で **テキスト VRAM をそのまま吸い出す**
  → 画面に出ている文字を、文字コードと属性バイトのレベルで確認できる
- 属性バイトを行ごとに集計する
  → 「色が意図どおりに付いているか」を目視ではなく数値で確認できる
- `info registers` で `CR0` を読む
  → PE ビットが立っているか＝プロテクトモードに入れたかが分かる
- `screendump` で PNG スクリーンショットを撮る（`build/screen.png`）
- `sendkey` でキー入力を送り込む

### キー入力の指定

```bash
python3 tools/run_qemu.py --keys "hello,spc,world,ret,abc,bs,esc"
```

- 英数字はそのまま 1 文字ずつ送られる
- `spc` / `ret`(=`enter`) / `esc` / `bs`(=`backspace`) / `tab` は特殊キー名

### ハマりどころ

QEMU のモニタコマンドの引数は**式として評価される**。
`pmemsave 0xb8000 4000 /tmp/vram.bin` のように**絶対パスを渡すと
先頭の `/` が除算演算子と解釈されて**
`invalid char 't' in expression` というエラーになる。
`run_qemu.py` では QEMU の作業ディレクトリを一時ディレクトリにして
相対ファイル名を渡すことで回避している。

## 2. VirtualBox による確認（実機に近い最終確認）

1. 新規 VM を作成（OS タイプ: Other/Unknown、メモリは最小構成でよい）
2. 「設定」→「ストレージ」→ フロッピーコントローラーが無ければ右クリックで追加
3. フロッピーコントローラー上の「空のフロッピーを追加」をクリック
4. 追加されたフロッピードライブを選択 → プルダウン横のディスクアイコン →
   「ディスクファイルを選択」→ `build/disk.img` を選択
5. 「設定」→「システム」→「マザーボード」→ 起動順序でフロッピーを最上位へ
6. 起動

**注意**: `disk.img` を差し替えて再検証するとき、VirtualBox 側にキャッシュが
残ることがある。フロッピーの割り当てを一度外して入れ直すと確実。

### VirtualBox のログの読み方

引き継ぎ資料 5章(2) の教訓。

- `/TRPM/ForwardRaw/TRAP/08`（ダブルフォルト）の発生回数が多い
  → 無限リブートループに陥っている強い兆候
- `BytesRead` / `ReqsRead`（ディスク読み込みリクエスト数）が想定より少ない
  → ディスク読み込み自体が失敗している可能性が高い

## 3. 機械語レベルでの検算

アセンブラの出力を鵜呑みにしない。特に複合的なアドレッシングモードを使ったときは
必ずバイト列を確認する（引き継ぎ資料 5章(3) の教訓）。

```bash
make dump       # disk.img の HEX ダンプ付きでビルド
make disasm     # objdump で逆アセンブル
```

nasm は `-l` オプションでリスティングファイルを吐くので、
`build/stage1.lst` / `build/stage2.lst` を見れば
「ソースの各行がどのバイト列になったか」が 1 対 1 で確認できる。

### 引き継ぎ資料の Stage2 v2 の検証結果

資料 2-3節 で手動バイトアセンブルされた 47 バイトは、
`src/boot/stage2_v2_color.asm` を nasm でアセンブルした結果と**完全に一致**した。
手動デコードに誤りは無かった。

```
0000: B8 00 B8 8E C0 BF 00 00 BE 21 7E 8A 04 3C 00 74
0010: 0E 26 88 05 26 C6 45 01 1A 83 C7 02 46 EB EC EB
0020: FE 48 45 4C 4C 4F 2C 20 57 4F 52 4C 44 21 00
```

QEMU で起動した結果、VRAM の 0 行目に `HELLO, WORLD!` の 13 文字が
属性 `0x1A`（背景=青 / 文字=明るい緑）で書き込まれていることを確認済み。

```bash
make v2
python3 tools/run_qemu.py
```
